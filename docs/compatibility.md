# Compatibility

The operating systems, runtimes, build tools and test runners that CI tests, for each preset. The
first table is generated by `npm run gen:checks` from the workflow files in `.github/workflows/`,
`package.json` and `.github/python-e2e-constraints.txt`, and a test fails when it is out of date. So
it shows what CI runs, not what someone remembered to write down.

- **Full suite**: the preset's whole test suite runs there (the `typescript`, `java-e2e`,
  `kotlin-e2e` and `python-e2e` workflows).
- **Sample run**: the `platforms` workflow runs the CLI the way a user does on a small sample
  project (`scripts/platforms/samples.mjs`). It runs `--all` once, then again after a change that
  adds one violation. The findings must match the Linux run under Node.js, apart from the
  differences in the second table. The samples are the TypeScript strict-clean fixture, a Gradle and
  a Maven Java project, and a Python project.

## Operating systems

- **Linux** runs every suite.
- **macOS** runs the samples, with no known differences.
- **Windows** (native, not WSL) runs the samples. These limits are by design:
  - Installing the base snapshot's dependencies, which nitpicker does when a change edits
    `package.json` or the lockfile, is refused, because Node.js does not start the package managers'
    `.cmd` shims without a shell. Run nitpicker in WSL for such changes; see
    [what it compares](usage.md#what-it-compares).
  - Python mutation testing is skipped with a descriptive `mutation-skipped` finding, because
    mutmut needs `fork`. Use WSL to run it.
  - Check the repository out with LF line endings (`git config core.autocrlf false`, or
    `* text=auto eol=lf` in `.gitattributes`). Git for Windows converts to CRLF by default, and then
    the Prettier check of the TypeScript and JavaScript presets reports every line.

  Gradle and Maven run through `gradlew.bat`, `mvnw.cmd` or the `gradle.bat` and `mvn.cmd` on the
  `PATH`, and a timed-out build is stopped with `taskkill /T /F`.

## Runtimes

nitpicker is a Node.js tool. It needs Node.js 22.14 or newer, and CI uses Node.js 24. The analyzers
nitpicker starts run on the runtime that started the CLI (`process.execPath`).

### Deno

Deno runs the installed CLI unmodified:

```sh
npm install --save-dev nitpicker typescript @types/node
deno run -A node_modules/nitpicker/core/cli.mjs
```

The `runtimes` job of the `platforms` workflow runs the TypeScript sample under the Deno version in
the table and compares the findings with Node.js. They match, except that the default TypeScript 7
type-check engine fails under Deno (`Bad file descriptor`, #476). Set the project's own TypeScript
as the engine:

```json
{ "tools": { "typescript": { "engine": "project" } } }
```

Only Vitest has been run under Deno. Jest, Mocha and `node:test` projects, and the Java, Kotlin and
Python presets, have not been tested under Deno. `DENO_NO_UPDATE_CHECK=1` stops Deno from checking
for a new release on every analyzer process it starts.

### Bun

Bun is not supported, and the maintainers decided against a Bun mode. nitpicker reads every child
report from a file (#475) and finds packages without `node:module`'s `findPackageJSON`, so it starts
under Bun. Bun 1.4.2 still fails in four places:

- `node:module` has no `stripTypeScriptTypes`, so every analyzer that loads the coverage reader
  fails to start (coding-standards, coupling, coverage, dead-code, duplicates, mutation, structure
  and test-runtime).
- The oxlint rule listing is cut off at about 220 KB when read through `execFile`, so the default
  oxlint lint engine fails. The ESLint engine (`"tools": { "eslint": { "engine": "eslint" } }`) works.
- The TypeScript 7 type check hangs until its timeout (#476). The `project` engine works.
- Stryker cannot start its worker server, so TypeScript mutation testing needs Node.js. Bun's own
  coverage has no branch data, which the coverage and CRAP checks need.

A project that installs with Bun is supported: the base snapshot's install uses `bun install` (see
[what it compares](usage.md#what-it-compares)), and only the CLI runs on Node.js.
