# Generated sources

Part of the [Java preset guide](../java-preset.md).

Findings on generated sources are dropped (`generated/generated-sources.mjs`, applied to the Java
and Kotlin presets on Gradle and Maven alike), so a generated file needs no `exclude`. A source is
generated when its leading comments carry the header a known generator writes (the shared list in
`shared/conventions/generator-marker.mjs`: protoc, Wire, jOOQ, Avro, ANTLR, JAXB, OpenAPI
Generator, Swagger Codegen, Thrift, Android's `R` and `BuildConfig`, or `Code generated by <tool>.
DO NOT EDIT.`), when it carries an `@Generated` annotation naming a known annotation processor
(MapStruct, Dagger, AutoValue, Immutables, Querydsl, the gRPC Java plugin, the Hibernate
metamodel generator, OpenAPI and Swagger generators, jOOQ, Room, Micronaut), when it lies under
`build/generated/` (javac, kapt and KSP output), `target/generated-sources/`,
`target/generated-test-sources/` or a `delombok` folder of the build output, or when it lies in a
`generated/`, `generated-sources/` or `gen/` folder and its first five lines say `@generated` or
`DO NOT EDIT`. Lombok's `delombok` writes no header, so its output counts through the build
folder. A generic marker in a normally named file, an `@Generated` annotation with another value
and a header below the code exempt nothing; hand-written code carrying `@Generated` (or any
annotation whose name contains `Generated`) stays the
`pmd/GeneratedOnHandWrittenCode` finding. The evals harness fails a case whose agent wrote one of
these markers into a file it wrote by hand.

## Tools skip generated source roots

Dropping findings is not the only step: the tools do not read generated roots at all, on Gradle and
Maven alike, so a large generator output costs no analysis time. A source root is generated when it
lies strictly inside the build directory (`build/` or `target/`, or the directory the build moves
it to), or when its path matches the build-output pattern above (`build/generated/`,
`target/generated-sources/`, `target/generated-test-sources/`, a `delombok` folder). The pattern
lives in `languages/java/gradle/generated/generated-roots.json`, which the Gradle init script and
the Maven code both read, so the two build tools agree. A build directory that is the module
directory, or holds it, makes no root generated by that test, so a project that builds into its
own root keeps its sources. Annotation processor output
(`generated-sources/annotations`, javac's `-s` directory) counts as generated too.

- **PMD, CPD, Checkstyle, the structure metrics and the format check** read only the hand-written
  roots. A module whose sources are all generated gets empty PMD, SpotBugs and Checkstyle reports.
- **SpotBugs** analyzes the class files of hand-written sources, listed one per line in a file given
  as `-analyzeFromFile`, so the list is not limited by command-line length. A class is generated
  when a generated source declares it, or the type it is nested in, or (Kotlin) the file facade,
  and no hand-written source declares it. The output directory stays on the aux classpath, so
  hand-written code that uses generated classes still resolves.
- **Error Prone** still compiles generated sources, because hand-written code depends on them, but
  runs no checks on them: `-XepExcludedPaths` names the generated roots (joined with a pattern the
  project declares itself). Error Prone matches the pattern against the file's decoded path, so a
  directory with spaces or non-ASCII letters is matched literally. Hand-written code annotated
  `@Generated` is still checked, so the fix-only checks can remove such annotations.

## `java.analyzeGeneratedSources`

`"java": { "analyzeGeneratedSources": true }` in `nitpicker.config.json` (a boolean; anything else is
a configuration error) turns the skipping off: every tool reads generated roots again, SpotBugs
analyzes every class, and Error Prone runs its checks on generated code. Findings in generated files
are still dropped from the report, as above. Use it when generated code is part of what the project
owns, or to compare timings. The setting is listed in [usage](../usage.md) with the other `java`
options.

SpotBugs reports a class by its package path. A SpotBugs finding whose class has no source file
under a project source root, such as a class compiled from `target/generated-sources/annotations`
(the Hibernate JPA metamodel `*_` classes), is dropped, never shown with a package-relative path.
