# Review rules

Part of the [Java preset guide](../java-preset.md).

Rules that carry review findings over from the TypeScript preset. Each works the same on Gradle
and Maven: the PMD rules are in the shared rule set files, and `spring/java-spring.e2e.test.mjs`
builds one Spring project (`java-e2e/fixtures/review-rules`, every expected violation marked with
`// violation: <rule>`) with both and asserts the same findings, and exactly the marked ones.
Every message names the allowed form and the exception that keeps code that is right.

**Rule set scopes.** `pmd-test-ruleset.xml` (and `spring-test-ruleset.xml` when the compile
classpath has Spring) run on test sources only, through the generated `pmd-tests.xml` that
excludes the main source directories. `pmd-main-ruleset.xml` (and `spring-ruleset.xml` with Spring)
run on main sources only, through the generated `pmd-main.xml` that excludes the test directories.
The init script and `maven/maven-lint.mjs` generate both, so the scopes are the same on both
builds. The main-only set holds PMD's `security` category, since tests encrypt with fixed keys, and the API
design rules (`ExhaustiveEnumPredicate`, `StaticForwardingWrapper`, `SingularAndPluralMember`, `TriStateBoolean`,
`ParameterMutation`, `CompatibilityShim`, `LegacyCalendarApi`): like the TypeScript preset's
`exhaustive-union-predicate`, `no-forwarding-wrapper`, `no-singular-and-plural-prop`,
`no-tri-state-boolean`, `no-parameter-mutation` and `no-compatibility-shim`, which run
on production files only, they leave test helpers alone, since tests are not an API anyone calls.
`UnboundedFanOut` and `UnboundedReactiveFanOut` are main-only too, like `unbounded-fan-out` in the other presets: a test that starts
many calls at once talks to fakes.
`UnboundedThreadPool` is main-only for the same reason: a test may start a cached pool for a few
tasks.
`ProcessWaitWithoutTimeout` is main-only too, like `require-process-timeout` and
`subprocess-without-timeout` in the other presets: a test run has its own time limits.
`HttpWithoutTimeout` is main-only too, like `kotlin-source/HttpWithoutTimeout`, the TypeScript preset's
`nitpicker/require-http-timeout` and the Python preset's `http-without-timeout`: a test talks to a local fake.
It runs in every Java project, with or without Spring. It does not report the clients the Spring rules
build (`RestTemplate`, `RestClient`, `WebClient`, the Spring request factories without an Apache client and a
`java.net.http.HttpClient` without `connectTimeout`): `SpringHttpClientTimeouts` and `SpringHttpClientPerCall`
own those, so one construction gets one finding. A Spring project can still get two findings on two lines: a
`java.net.http.HttpClient` built without `connectTimeout` and a request sent with it built without `timeout`.
`new RestTemplate()` is reported only where the Spring rules report it, in setup code or per call.
`RecursiveMapUpdate` is main-only as well, like its Kotlin counterpart: the in-flight and cache maps it
guards live in production code.
It also holds `ClassLoadEffect`, the counterpart of the TypeScript preset's
`nitpicker/report-module-load-effects`: a test class may open a file or start a server in a static
setup, production code may not.
`UnclosedInlineResource` is main-only as well: a test that reads a fixture with
`getClass().getResourceAsStream("order.json").readAllBytes()` ends with its JVM, while a server
leaks a handle on every request.
Two manifest flags feed the messages and checks below: `testAwaitility` (Awaitility on the test
classpath) and `published` (a library module that is deployed, see `test-only-export`).

**Precision notes.**

- `FixedSleepInTest` and `NegativeWaitInTest` match by resolved type (`java.lang.Thread`,
  `java.util.concurrent.TimeUnit`, `LockSupport`, `org.mockito.Mockito`, Awaitility's
  `ConditionFactory`, Playwright's `Page` and `Frame`), so a project's own `sleep` method is not
  flagged. A polling loop is a `while`, `do` or `for` loop with a condition other than `true`, or a
  `while (true)` / `for (;;)` loop that reads the clock (`System.nanoTime()`,
  `System.currentTimeMillis()`, `Instant.now()`, a `Clock`). Both Awaitility and a deadline loop
  are valid, so the message follows the project (`messages/wait-advice.mjs`): it names Awaitility
  when the module has it on the test classpath or a test file imports `org.awaitility`, and it
  then says that `pollDelay(...).until(() -> true)` is a fixed sleep too.
- `MockedSubjectInTest` and `StaticMockOfProjectType` match Mockito by resolved signature and report
  the mocked type. The Node side (`messages/mocks/project-mocks.mjs`) keeps a finding only when that
  type is declared in the project's main sources (a source root of the module, or a `src/main` file
  of any module), and names it in the message. A partial mock is the only seam in some legacy code;
  the exception route covers it.
- `GlobalStateLeakInTest` treats a class as the project's when it has no import (the same package) or is imported
  from a package under the test's package root: the first two segments for a root such as `com`, `org`, `io` or a
  country code (`com.acme`), three under `io.github` and the other code hosts, otherwise the first segment (`shop`). A
  library's statics (`RestAssured.baseURI = ...`) and a class declared in the test file are not checked. The JDK forms
  match by resolved type. A restore in a superclass, in another class or through a static import is not followed: give
  the test class its own `@AfterEach`, or add an exception. In a class without a test method (a helper or an
  extension), a restore anywhere in the class counts. The Kotlin preset has the same rule id, and the TypeScript
  (`nitpicker/fake-timers-require-restore`) and Python (`global-state-leak-in-test`) presets the same check for their
  globals.
- `ServerOrContainerPerTest` matches by resolved type, so the library must be on the test
  classpath. An object made for each test is a new object (`new X(...).start()`, a local
  variable, a field the hook assigns), an instance field in a class without
  `@TestInstance(PER_CLASS)` (JUnit makes one instance per test), or a field that an `@AfterEach`,
  `@After` or `@AfterMethod` stops (`stop`, `close`, `shutdown`). A `start()` on a static field,
  or on an instance field of a `PER_CLASS` class, is left alone, since these starts do nothing
  once the server or container runs. `SpringApplication.run`, `ProcessBuilder.start`,
  `Runtime.exec`, `startClientAndServer` and an `EmbeddedKafkaBroker` start something new on
  every call. A container is also found through a raw or `var` local, a field, or a builder chain
  on a new container (`new GenericContainer<>(...).withEnv(...).start()`). A start in a helper
  that test methods (not hooks) call is not followed. Two starts in different test methods count
  as the same when their statements, and the declaration of a local they start, have the same
  names and literals; tests that start servers with different settings are left alone. The TypeScript preset has the same check in
  `nitpicker/no-server-or-worker-per-test` and `nitpicker/no-node-process-per-test`.
- `ExhaustiveEnumPredicate` needs at least two comparisons with distinct constants of one enum on
  one subject. A condition in an `if` or a loop, or a predicate passed as an argument, is not a
  value and is not flagged. The Node side (`adapters/review-rules/enum-predicates.mjs`) then keeps
  a finding only when the enum is declared in the project's sources (same package, imported, or
  the only enum with those constants), has at least three constants and the predicate lists some
  but not all of them; the message names the enum. A static-imported constant is resolved through
  its `import static`, and through a wildcard static import when one project enum declares it.
  Library enums (`TimeUnit`, `HttpStatus`) are not the project's to classify. A `switch` (expression
  or statement) is flagged when it has a `default`, every other branch yields one boolean constant
  (`case A, B -> true`, `case A: return true;`, `yield true`) or falls through to such a branch, the
  `default` yields the other constant, and at least two constants are listed (a label that falls
  through into `default` is not listed). So adding a `default` that yields `false` does not clear the
  finding; removing the `default` and listing every constant does. The Node side reads the enum from
  qualified labels (`case Status.NEW`), else from the declared type of a variable subject
  (`Status s`), else from every project enum that declares all the labels: the finding is kept only
  when the switch is partial for each of them, and names the enum when there is one. A `switch
(this)` inside the enum itself is one of its own methods and is not flagged, like `this == A`.
- `StaticForwardingWrapper` skips annotated methods, generic methods, `main`, `valueOf`,
  `fromString`, `of` and `from` (names frameworks and callers look up), methods of Spring
  stereotype and configuration classes, wrappers around `copyOf`, `copyOfRange`, `unmodifiable*`,
  `synchronized*` and `checked*` (they change the type or the guarantees), and wrappers that add
  type arguments, reorder or drop parameters.
- `ClassLoadEffect` treats lambdas, method references, anonymous class methods and local classes as
  run later, so a `Supplier` field or a `Runnable` built at load is fine, and a lambda that a
  static block runs at once (`list.forEach(...)`) is not followed. A helper is followed one level
  and only within its own class: the call must have no receiver, `this` or the class name, and PMD
  must resolve it to that method, so `List.of()` or `Objects.toString(x)` in a `static` field does
  not make a method `of` or `toString` of the class a helper, and of two overloads only the one the
  arguments select is (`read(1)` runs `read(int)`, not `read(String)`). A constructor counts only
  when the class's own `static` code creates an instance with arguments that select it, or a
  `this(...)` call in that constructor reaches it, so a value class with
  `static final Money ZERO = new Money(0)` keeps a `Money(String file)` constructor that reads a
  file. A call into another class's helper, or a `static` field of another class that creates this
  one, is not followed: that is the lazy holder the message suggests
  (`private static final class Holder { static final Db INSTANCE = new Db(); }`), which runs only
  when `Holder.INSTANCE` is first read. The class that declares `public static void main(String[])`
  is not checked: running at load is what an entry point does (a nested class of it is). That
  includes a `@SpringBootApplication` class with `main`; Spring `@Configuration` classes and a
  `@SpringBootApplication` class without `main` get no pass: the container creates their beans
  after the class has loaded, so their `static` blocks still run at load, in every test slice that
  touches them, while their `@Bean` methods and constructors are not load-time code. Reading a classpath resource (`getResourceAsStream`) is allowed: it is part of
  the program, not an outside system. `System.getenv` and `System.getProperty` reads are left to
  `SpringTypedConfiguration` in a Spring project and are allowed elsewhere. `new HikariDataSource()`
  without a configuration, `new Socket()` and `new ServerSocket()` without arguments connect nothing
  and pass. `Security.addProvider` and `System.loadLibrary` are allowed: registering a provider and
  loading a native library are the usual work of a static block. `System.exit`, `Runtime.exit` and
  `Runtime.halt` are left to `DoNotTerminateVM` (and Error Prone's `SystemExitOutsideMain`), which
  report them anywhere outside `main`.
- `ClassLoadEffect` compared with the TypeScript rule: clock reads (`Instant.now()`,
  `System.currentTimeMillis()`), random values (`new Random()`, `UUID.randomUUID()`) and
  environment reads stay allowed in a `static` field, since they change nothing outside the class
  and a `Clock` or `Random` field is how JVM code holds them; TypeScript reports `Date.now()`,
  `Math.random()` and any `process.*` call. The JVM-wide settings `process.*` stands for there
  (`System.setProperty`, `setOut`, `setErr`, shutdown hooks) are reported here. `Thread.sleep`,
  which blocks the loading thread as a module-level `time.sleep` blocks a Python import, is
  reported; TypeScript has no blocking sleep to report.
- `ClassLoadEffect` names the call, the class and the member from the source at the finding's
  location (`messages/load-effects.mjs`), so a finding in a helper reads
  `` `DriverManager.getConnection(...)` runs while Db loads (in method open, which static field CONNECTION calls) ``.
  The same pass gives the finding its identity: the class, the member that runs the call and the
  call text (`Db.open(): DriverManager.getConnection(...)`), with no line number, so a finding keeps
  its identity when lines above it move, and a changed call is a new finding.
- `ClassLoadEffect` limits: overloads are told apart by parameter count and by the declared type of
  each parameter, which PMD resolves through single-type imports, types of the file, star imports,
  `java.lang` and the package; two same-arity overloads whose reference parameter types both match
  an argument (a star-imported type that shares a simple name with a class of the package) are both
  taken as called. A class whose `static` code creates an instance through another class's factory
  is not followed.
- `SingularAndPluralMember` compares declared types by simple name, with primitives boxed, and is
  reported on the plural member. Parameters count only when both are annotated `@Nullable` (any
  package), the Java form of the optional parameters the TypeScript and Python presets check:
  `contains(String role, Set<String> roles)` takes both and is not reported. `@Override` methods,
  the constructors of records, varargs (`record Keys(String key, String... keys)`) and the fields of
  a class with any other method (a service that keeps a default and a list of handlers) or with a
  Spring stereotype (`@Component`, `@Service`, `@Repository`, `@Controller`, `@RestController`,
  `@Configuration`) are not checked, and neither is a singular that is itself generic
  (`List<String> tag` beside `List<List<String>> tags`). Two members whose meanings differ (`owner` for the main owner beside `owners` for the
  co-owners) are the case for an exception with a reason.
- `UnboundedFanOut` is the rule the TypeScript and Python presets call `unbounded-fan-out`. A call
  counts as remote or message by the resolved type of its receiver: `java.net.http.HttpClient`,
  Spring's `RestOperations`, `RestClient` and `WebClient`, OkHttp, the Apache HTTP clients, gRPC
  stubs, AWS SDK v2 clients, JAX-RS invocations, Retrofit calls, Kafka producers and
  `KafkaOperations`, `AmqpTemplate`, `JmsOperations`, JMS producers, `MessageSendingOperations`,
  `StreamBridge` and RabbitMQ channels. Database calls are left to the per-item I/O rules. The task
  may reach the call through same-class helpers, up to three calls deep. An executor counts as
  unbounded only when the field or local it is read from is always created by
  `Executors.newCachedThreadPool`, `newVirtualThreadPerTaskExecutor`, `newThreadPerTaskExecutor`
  or `ForkJoinPool.commonPool`; a parameter, an injected executor or a fixed pool is never
  reported. These pass: a `Semaphore` acquired in the loop body, the task or a helper; a source
  that is fixed (`List.of`, `Arrays.asList` of listed values, `Stream.of`, an array initializer, enum `values()`, a
  `final` field holding one of those) or cut to size (`limit` or `subList` whose size does not
  read the collection's own size, so `Math.min(20, items.size())` passes and `items.size()` does
  not; a chunk variable over `partition`, `chunked` or `batches`; a local holding a cut list); a
  worker pool sized by a count (`IntStream.range(0, workers)`, `for (int i = 0; i < workers; i++)`)
  while a count read from a collection's size stays a fan-out over that collection; a body that
  waits for the task (`join`, `get`, `Thread.join`) before the next element; and a stream whose
  next lazy stage joins the futures (`.map(CompletableFuture::join)` before any
  `collect`/`toList`). A task started per batch of `Lists.partition(items, 20)` is reported, since
  the number of batches grows with the collection. The message names the iterated collection and
  the call that starts the tasks (`messages/fan-out/fan-out-details.mjs`), read from the source at the
  reported line. Limits: a `while (it.hasNext())` loop, a list of callables filled in a loop and
  then passed to `invokeAll`, a `ThreadPoolExecutor` constructed with an unbounded maximum and
  helpers of other classes are not followed; PMD resolves types from the compile classpath, so a
  client type the build does not resolve is not recognized.
- `UnboundedReactiveFanOut` is the Reactor counterpart of `UnboundedFanOut`, the rule the TypeScript
  preset calls `unbounded-reactive-fan-out` for RxJS. `Mono.zip`, `Mono.when` and `Flux.zip` over an
  `Iterable` (also `Mono.zipDelayError` and `Mono.whenDelayError`), and `Flux.merge` over an array,
  subscribe to every source at once; `flatMap`, `flatMapSequential`, and `Flux.merge` and
  `Flux.mergeSequential` over an `Iterable`, without a concurrency argument, run up to 256 at once (Reactor's
  `Queues.SMALL_BUFFER_SIZE`), a bound but a high one, so they are reported only when the element
  work makes a remote or message call, recognized by the same client types and same-class helpers
  (also a `this::fetch` reference) as `UnboundedFanOut`. A `flatMap` is checked when its chain
  starts at `Flux.fromIterable`, `fromStream` or `fromArray`; a combinator when its first argument,
  or the local it names, is a stream `map` over a collection. These pass: a concurrency argument
  (`flatMap(this::fetch, 8)`), `concatMap`, a `buffer`, `window`, `collectList`, `reduce`, or
  a `take` or `limitRequest` whose size does not read the collection's size in the chain before
  `flatMap` (one batch call per chunk is the allowed form), a fixed collection as in
  `UnboundedFanOut`, two or three publishers passed one by one (`Mono.zip(a, b)`), and a `Flux`
  that does not start from a collection (a parameter, a query result), which may be a stream of
  events rather than a fan-out. Limits: a source `Flux` held in a local is not followed, and Kotlin
  Flow is covered by the Kotlin preset only. `flatMapDelayError` and the `DelayError` merges always
  take a concurrency argument, so they are not checked.
- `TriStateBoolean` matches the simple name `Boolean` as the whole type, so `Optional<Boolean>`,
  `List<Boolean>` and a primitive `boolean` pass. Data mapped from outside is exempt in every
  preset: a Java parameter, field or record component carrying `@RequestParam`, `@RequestBody`,
  `@RequestHeader`, `@PathVariable`, `@JsonProperty`, `@Column` or `@Field`, and the fields of a class
  annotated `@Entity`, `@Embeddable`, `@MappedSuperclass` or `@Document` (the Kotlin counterpart
  skips the same annotations, the Python one pydantic and ORM model fields, the TypeScript one
  properties). The Kotlin counterpart is `Boolean?` and the TypeScript one is
  `boolean | undefined`.
- `ParameterMutation` reports the parameter use. It needs the resolved type to be a `java.util.Collection`
  or `Map` for method calls, so a `StringBuilder` or a stream sink is not a changed argument. A
  parameter stored in a field (`this.items = items`) or a local variable (`var alias = items`) and
  changed through that name is the same list and is reported. Only a rebind to a copy of the
  parameter that comes before the change makes it a change to the copy
  (`items = new ArrayList<>(items); items.add(x)`); `if (items == null) items = new ArrayList<>();`
  followed by `items.add(x)` still changes the caller's list in the other branch. A private
  method or constructor, a method of a private, local or anonymous class, and every `@Override`
  method (whose signature the interface fixes) are helpers, not API. A concurrent type that exists to
  share work (`BlockingQueue`, `BlockingDeque`, `TransferQueue`, `ConcurrentMap`,
  `ConcurrentLinkedQueue`, `ConcurrentLinkedDeque`, `CopyOnWriteArrayList`, `CopyOnWriteArraySet`,
  `ConcurrentSkipListSet`) is not reported. The array form matches the assigned side only
  (`values[0] = 1`, `grid[0][1] = 3`, `counts[0]++`), not `v = values[0]` or `t += values[1]`. A copy
  is the allowed form: `new ArrayList<>(items)`, `List.copyOf(items)`,
  `Arrays.copyOf(counts, counts.length)`.
- `CompatibilityShim` reports the annotation, so the deprecated declaration is deleted together with
  its callers. The javadoc `@deprecated` tag without the annotation is `DepAnn` of Error Prone,
  which asks for the annotation; once added, `CompatibilityShim` reports it, so the two together
  forbid both forms. A call of a deprecated API is reported by the compiler's deprecation lint. Java
  has no alias declaration, so the TypeScript `export const Old = New` form has no counterpart.
- A number tested for truth (`if (count)`), which the TypeScript preset reports as
  `nitpicker/strict-boolean-expressions` and the Python preset as `number-truthiness`, has no
  counterpart: a Java condition must be a `boolean`, so the compiler rejects it.
- `UnclosedInlineResource` covers the closeables that have no variable, which PMD's `CloseResource`
  (it tracks locals) never sees and SpotBugs reports only for some types. Run by hand on the
  rule's review-rules fixture (`shop/resources/Leaks.java`), SpotBugs 4.9.3 (`OS_OPEN_STREAM`,
  `ODR_OPEN_DATABASE_RESOURCE`, `OBL_UNSATISFIED_OBLIGATION`) found 6 of the 12 shapes and missed every stream returned through an interface (Spring's `Resource`,
  `InputStreamSource`), every closeable passed as an argument and `new URLClassLoader(urls)`; on
  the lines both report, the SpotBugs finding is dropped (see the overlap list above). Java streams
  (`Files.lines`, `Files.walk`) are left to Error Prone's `StreamResourceLeak`. Not reported: the
  in-memory types `ByteArrayInputStream`, `ByteArrayOutputStream`, `StringReader`, `StringWriter`,
  `CharArrayReader` and `CharArrayWriter`, a Jackson `JsonParser` or `JsonGenerator`, a `Scanner`
  over a `String`, a `Formatter` over a `StringBuilder`, an `ExecutorService` and a
  `java.net.http.HttpClient` (both `AutoCloseable` since Java 19 and 21, but pools and clients, not
  handles), a wrapper around a closeable someone else owns (`new PrintWriter(writer)`,
  `new InputStreamReader(System.in)`), the streams of a `Process`, a `Socket`, a `ZipFile` or a
  servlet request or response, a closeable passed to a Spring `DisposableBean`
  (`new HttpComponentsClientHttpRequestFactory(HttpClients.createDefault())` closes the client in
  `destroy()`), and a call on a closeable that is not one of the opening names above
  (`writer.append(text)`, `sessionFactory.getCurrentSession()`), since those return a closeable its
  owner releases. A `.close()` on the inline closeable passes. Limits: types come from the compile
  classpath, so a closeable the build does not resolve is not reported, and a project method that
  opens a resource under another name (`fetch()`) is not followed.
- `LegacyCalendarApi` is the part of the naive-datetime check that Error Prone does not cover:
  `JavaTimeDefaultTimeZone` (`now()` without a clock or zone) and `JavaUtilDate`
  (`java.util.Date`) are on by default. It reports only the overloads without a zone;
  `Calendar.getInstance(zone)` and `new GregorianCalendar(zone)` are allowed, and so is a
  `SimpleDateFormat` whose variable gets `setTimeZone(...)`. It takes over the lines that
  `AvoidCalendarDateCreation`, `SimpleDateFormatNeedsLocale` and Error Prone's `DefaultLocale`
  also report (see the overlap list above).
- `UriCreateDynamic` asks PMD whether the argument is a compile-time constant, so a `static final`
  string built from literals passes and a field set from `System.getenv` or a setting does not: a bad
  configured value still fails only when the code runs, and the exception route covers a
  configuration class that has to read one. `new URI(text)` is not checked, since Java makes the
  caller handle its `URISyntaxException`. A `try` counts only in the same method, constructor or
  initializer: a lambda inside it counts (also one that runs later, a known gap), an anonymous or
  local class that calls `URI.create` later does not.
  The Kotlin preset has the same rule as `kotlin-source/UriCreateDynamic`, and the TypeScript preset
  reports `new URL(text)` the same way (`nitpicker/no-unhandled-url-parse`).
- `UnquotedRegexValue` reports a value that a regex API compiles without quoting. `String.split`,
  `splitWithDelimiters`, `matches`, `replaceAll` and `replaceFirst` take a regex, so a runtime
  separator such as `"."` or `"|"` splits on every character; the argument counts as runtime when it
  reads a parameter, a local variable, a field that is not `static final` or `this.field`, outside a
  `Pattern.quote(...)` call (`UPPER_CASE` names count as constants, since a static import hides the
  declaration). `Pattern.compile(pattern)` with a whole pattern is the explicit form and passes;
  `Pattern.compile` and `Pattern.matches` are reported only when a runtime value is joined into the
  pattern with `+`. The String methods do not read as a regex API (a caller writes
  `line.split(separator)` for plain text), so a lone runtime value is reported there, while
  `Pattern.compile` is the explicit form for a pattern held in a variable; a field meant as a
  pattern belongs in a `Pattern` (`PATTERN.matcher(text).matches()`). Numbers, booleans and characters, the condition of a `?:`,
  `Pattern::quote` and a local of the same method initialized with a constant or a `Pattern.quote`
  call pass; a local built from constants in another way is still reported (XPath does not follow
  it), and the exception route covers that case. The Kotlin preset has the same rule as
  `kotlin-source/UnquotedRegexValue`, the TypeScript preset reports `new RegExp` patterns built
  from a parameter (`nitpicker/no-string-as-regex`), and the Python preset reports `re` patterns
  built from an argument (`regex-unescaped-value`).
- `PlainTextRegex` reports `replaceAll` with a constant pattern that has no metacharacters
  (`\^$.|?*+()[]{}`): `replace` does the same without compiling a regex on every call and reads the
  replacement literally. `split` with a constant is left alone, since `String.split` takes a fast
  path for a one-character separator. The Kotlin preset reports `Regex("text")` passed to
  `replace`, `replaceFirst`, `split` or `contains` as `kotlin-source/PlainTextRegex`.
- `LogFormatArguments` and `LogExceptionFirst` (in `pmd-ruleset.xml`, so main and test sources)
  cover the logging APIs whose format neither PMD's `InvalidLogMessageFormat` (SLF4J and Log4j 2
  `{}`) nor Error Prone's `FormatString` (methods annotated `@FormatMethod`) reads. They find the
  logger by its type, so a logger the build cannot resolve (a Lombok `@JBossLog` field without
  delombok) is not checked. The format is read from a literal, a text block, a constant of the same
  file or these joined with `+`; a constant from another class is a compile-time constant PMD
  cannot read here, so it passes. `java.util.logging` formats only when there are parameters, so
  `log(Level, String, Throwable)` with a placeholder is flagged and one without is not. Log4j 2
  takes an exception after the last argument as the event's exception, so that is not flagged; JBoss
  Logging does not, so `LogExceptionFirst` reports it, alone when the exception fills the last
  placeholder and the count matches. `null` is not taken for an exception. The Kotlin preset has the same rules as
  `kotlin-source/LogFormatArguments` and `kotlin-source/LogExceptionFirst`. Python is covered by
  ruff `PLE1205`, `PLE1206` and the `G` rules. TypeScript has no counterpart yet: `console.*` and
  `util.format` append an argument with no placeholder and print a placeholder with no argument as
  written, so nothing is lost there, but pino drops a value passed after a message without a
  placeholder for it (`log.info("loaded config", config)`), and so does winston without
  `format.splat()`; that needs its own rule for those libraries.
- `RecursiveMapUpdate` follows the `Map` contract: the function passed to `computeIfAbsent`,
  `compute`, `computeIfPresent` or `merge` must not change the map. A `ConcurrentHashMap` throws
  `IllegalStateException: Recursive update` or deadlocks, a `HashMap` throws
  `ConcurrentModificationException`. The common form is an in-flight map whose cleanup
  (`remove(key)`) is attached to the future created inside the function, so a future that completes
  at once removes the entry while the map is still computing it. The allowed form attaches the
  cleanup to the value `computeIfAbsent` returns
  (`map.computeIfAbsent(key, k -> start(k)).whenComplete((r, e) -> map.remove(key, r))`). Helpers are
  followed one level and only for a field map: a method of the same class with that name and as many
  parameters as the call passes (or as the function takes, for a `this::helper` or
  `EnclosingClass::helper` reference). A local or parameter of the same name that shadows the field
  keeps a call off, and `Outer.this.map` is never taken for the inner class's `map`. A key expression (`map.computeIfAbsent(map.remove(k), ...)`)
  runs before the function and is not reported. Error Prone and SpotBugs, as enabled, check only
  check-then-act sequences and `ComputeIfAbsentAmbiguousReference`.
- `DefaultTimeZone` reports the default-zone lookups that `JavaTimeDefaultTimeZone` leaves alone:
  `ZoneId.systemDefault()` (which Error Prone itself suggests as the replacement for `now()`) and
  `TimeZone.getDefault()`. Together with `LegacyCalendarApi` and the two Error Prone checks this is
  the Java counterpart of Python's ruff `DTZ` rules and of the TypeScript preset's
  `nitpicker/no-local-time-zone`.
- `test-only-export` (`adapters/review-rules/test-only-classes.mjs`, run project-wide) reads
  `jdeps.txt`, `jdeps-classes.txt` and `jdeps-test.txt` of every module and resolves a class to its
  own module first. A main class is reported when test classes use it and no other main class
  does, unless:
  - it carries a wiring annotation, directly or through a project annotation that carries one
    (`adapters/review-rules/test-only-usage.mjs`): Spring stereotypes, `@Configuration`,
    `@SpringBootApplication`, `@AutoConfiguration`, `@ConfigurationProperties`, actuator
    `@Endpoint` and its variants, `@FeignClient`, Spring Data repositories, JPA `@Entity`,
    `@Embeddable`, `@MappedSuperclass` and `@Converter`, `@Named`, `@Singleton`, CDI scopes,
    interceptors and decorators, EJB beans, JAX-RS `@Path`, `@ApplicationPath` and `@Provider`,
    servlet `@WebServlet`, `@WebFilter` and `@WebListener`, `@ServerEndpoint`, Spring Boot
    `@SpringBootConfiguration` and `@JsonComponent`, Micronaut controllers, clients, factories,
    `@ConfigurationProperties`, `@Context`, `@Prototype`, `@Bean` and filters, MicroProfile
    `@RegisterRestClient` and `@ConfigProperties`, SmallRye `@ConfigMapping`, Quarkus `@Startup`;
    a class also counts as wired when one of its methods or parameters carries a framework callback
    annotation: `@Bean`, `@Scheduled` (Spring, Micronaut, Quarkus), `@EventListener`,
    `@TransactionalEventListener`, `@KafkaListener`, `@RabbitListener`, `@JmsListener`, AWS
    `@SqsListener`, `@MessageMapping`, MicroProfile `@Incoming` and `@Outgoing`, CDI `@Observes`.
    jdeps names every annotation a class uses, so a method annotation shows as a class dependency.
    Meta-annotations are followed only for the project's own annotations: a library annotation's
    own annotations are not in the reports, so the known ones are listed;
  - it has an entry point: a Java `static void main`, a Kotlin `@JvmStatic fun main`, or a Kotlin
    file with a top-level `fun main` (its `FileKt` facade);
  - its qualified name appears in a file the project reads by name: main sources, resources
    (`logback.xml`, `META-INF/spring/...`, `META-INF/services/...`), `src/main/webapp` (`web.xml`),
    or a file directly in the root or a module folder (build scripts with `implementationClass`,
    `Main-Class` or a shade `mainClass`, `template.yaml`, `plugin.xml`), and a `Dockerfile`,
    `*.Dockerfile` or `Containerfile` in any folder outside build output; comments (`//` and
    `/* */` in Java, Kotlin and Gradle scripts, `<!-- -->` in XML and `pom.xml`, `#` in YAML, TOML,
    properties and container files) and documents (`.md`, `.adoc`, `.rst`, `.txt`) not counted;
  - its simple name appears in the code of a main source file that sees its package (same package
    or a wildcard import);
  - or its module is a published library: on Gradle a project with a `publishing` publication, on
    Maven a `jar`, `bundle` or `maven-plugin` module with `distributionManagement` or a publishing
    plugin (`central-publishing-maven-plugin`, `nexus-staging-maven-plugin`,
    `maven-release-plugin`) whose deploy is not skipped. Its classes are its consumers' API, so its
    own and its sibling modules' tests are legitimate callers. A module with an entry point or a
    `@SpringBootApplication` is an application, not a library, even when it is deployed.

  Kotlin sources are read the same way: each top-level class, object or interface of a `.kt` file
  is a declaration, and a file with top-level functions or properties declares its `FileKt` facade
  (or the `@file:JvmName` name). The message names the exception for a class that a file
  nitpicker does not read loads by name. A module without all three reports is skipped.

**Not built.** Unused builder parameters (a Lombok `@Builder` or record builder field no caller
sets) are not checked: builders are filled by reflection (Jackson's `@Jacksonized`, MapStruct,
Spring binding) as often as by calls, and a text match on `.name(` collides with every method of
that name, so the rule would need compiler symbol facts to stay precise.
